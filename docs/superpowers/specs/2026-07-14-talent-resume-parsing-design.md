# 人才库简历解析优化设计

**日期**：2026-07-14  
**范围**：`/Users/yq/Documents/zhihr/talent-pool` 人才库管理系统  
**主题**：提升 PDF/Word 简历解析准确率，自动提取姓名、联系方式、学历、工作年限、工作经历等关键字段。

---

## 1. 背景与问题

当前 `api/src/modules/talent_parsers.js` 对 PDF/Word 简历的解析能力较弱：

- 仅通过正则提取手机号、邮箱，并取前 10 行作为 `summary`。
- **无法提取姓名**，导致用户上传简历后仍需手动填写核心信息。
- 不识别学历、目标岗位、工作年限、技能、工作经历等字段。
- 前端 `CandidateForm.vue` 即使后端返回了更多字段，也只回填手机号、邮箱、摘要。

这直接降低了"上传简历自动创建候选人"流程的价值。

---

## 2. 目标

1. **提高 PDF/Word 简历关键字段提取准确率**，至少覆盖：
   - 姓名
   - 手机号、邮箱
   - 目标岗位 / 期望职位
   - 学历、毕业院校、专业
   - 工作年限
   - 技能标签
   - 完整工作经历（公司、职位、时间段、描述）
2. **前端自动回填解析结果**，减少手工录入。
3. **对低置信字段给出明显提示**，引导用户人工确认。
4. **保持纯规则本地解析**，不依赖外部 LLM API，符合 Cloudflare Workers 环境约束。

---

## 3. 非目标

- 本期不改造数据库表结构，继续使用 `talent_candidates` 与 `talent_work_experiences`。
- 本期不做简历全文检索（full-text search），但结构化字段的完善会间接改善列表筛选体验。
- 本期不处理扫描版 PDF 的图片 OCR。

---

## 4. 总体方案

采用**分区块规则解析 + 置信度评分**方案：

1. 使用现有 Workers 兼容库（`unpdf`、`fflate`）提取 PDF/Word 纯文本。
2. 对文本进行清洗（去页眉页脚、合并断行、统一空白）。
3. 按常见简历结构切分为若干区块：个人信息、教育经历、工作经历、技能/自我评价、其他。
4. 在每个区块内应用针对性规则提取字段，并为每个字段计算置信度。
5. 返回结构化 JSON，前端根据置信度对字段做视觉提示。

```
PDF/Word 文件
    ↓
unpdf / fflate 提取纯文本
    ↓
文本清洗与标准化
    ↓
区块分割（个人信息 / 教育 / 工作 / 技能）
    ↓
分字段规则提取 + 置信度打分
    ↓
返回结构化 JSON + 原始文本片段
```

## 5. 后端解析详细设计

### 5.1 模块位置

- 主要逻辑写入 `api/src/modules/talent_parsers.js`。
- `api/src/modules/talent.js` 中的 `parseResume` 保持接口不变，仅消费新结构。

### 5.2 输出结构

`parseFile(fileName, arrayBuffer)` 统一返回：

```json
{
  "name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "position": "高级前端工程师",
  "education": "本科",
  "school": "某某大学",
  "major": "计算机科学与技术",
  "experience_years": 5,
  "skills": ["Vue", "React", "Node.js"],
  "summary": "简要自我评价文本",
  "experiences": [
    {
      "company": "ABC 科技",
      "title": "前端工程师",
      "start_date": "2020-03",
      "end_date": "2023-05",
      "description": "负责公司核心产品前端开发..."
    }
  ],
  "raw_text": "清洗后的完整简历文本（用于调试/后续扩展）",
  "confidence": {
    "name": "high",
    "phone": "high",
    "email": "high",
    "position": "medium",
    "education": "medium",
    "school": "low",
    "major": "low",
    "experience_years": "medium",
    "skills": "medium",
    "experiences": "medium"
  }
}
```

字段不存在时返回 `null` 或空数组，不省略字段。

### 5.3 文本清洗

- 将 Windows 换行 `\r\n` 统一为 `\n`。
- 合并由 PDF 断行导致的单行短句：如果连续多行长度都较短且不以标点结尾，则合并为一行。
- 移除明显页眉/页脚（如重复出现的"第 X 页"、公司 Logo、URL）。
- 统一中/英文冒号、空格。

### 5.4 区块分割

基于关键词启发式识别区块边界：

| 区块 | 触发关键词 |
|------|-----------|
| 个人信息 | 姓名、Name、个人信息、基本信息、联系方式 |
| 教育经历 | 教育背景、教育经历、学历、毕业院校、Education |
| 工作经历 | 工作经历、工作经验、工作履历、实习经历、Experience |
| 技能/评价 | 技能、专业技能、Skills、自我评价、个人优势 |
| 其他 | 项目经历、证书、语言能力 |

实现时使用行级别的状态机，按关键词命中切换当前区块；未命中区块的内容暂归入"未分类"，供后续字段回退查找。

### 5.5 字段提取规则

#### 姓名

- **高置信**：匹配 `"姓名[：:]\s*([^\n]{2,20})"` 或 `"Name[：:]\s*([^\n]{2,20})"`。
- **中置信**：在个人信息区块前 5 行中，取最短的中文姓名模式（2-4 个汉字），并过滤常见公司/学校/岗位黑名单。
- **低置信**：在全文前 10 行中按同样规则查找。

#### 手机号与邮箱

- 使用严格正则：
  - 手机号：`1[3-9]\d{9}`，并校验号段。
  - 邮箱：`[\w.+-]+@[\w.-]+\.[A-Za-z]{2,}`，过滤明显测试邮箱。
- 命中多个时取第一个。

#### 目标岗位

- 匹配关键词后的值：`意向岗位|期望职位|应聘岗位|求职意向|目标岗位|Position\s*Wanted|Job\s*Objective`。
- 取值后过滤停用词（"面议"、"不限"）。

#### 学历

- 直接匹配关键词：`博士、硕士、本科、大专、专科、高中、中专、MBA`。
- 在学校/教育区块内优先命中。
- 学校名通过常见后缀识别（大学、学院、学校、University、College）。
- 专业名结合"专业"后缀或常见专业词库。

#### 工作年限

- 直接匹配：`(\d+)\s*[年余]?\s*(工作|相关|开发|从业)?\s*经验`。
- 若未命中，从工作经历时间跨度计算：最早开始时间到最晚结束时间（"至今"按当前日期）。

#### 技能

- 在技能区块提取逗号、顿号、换行分隔的词条。
- 维护一个常见技术栈词库做过滤/补全，避免把公司名当成技能。
- 返回数组，最多 20 个。

#### 工作经历

- 在工作经历区块内按时间线索引切分条目。
- 识别时间模式：
  - `YYYY.MM - YYYY.MM`
  - `YYYY/MM - YYYY/MM`
  - `YYYY.MM - 至今`
  - `YYYY 年 MM 月 - YYYY 年 MM 月`
- 每条经历提取：
  - **公司**：时间前或后的短文本，含"公司、科技、网络、集团、Corp、Ltd"等后缀，或全大写/中文公司名。
  - **职位**：时间附近的职位类词汇（工程师、经理、总监、主管、开发、产品经理）。
  - **时间段**：解析为 `start_date`、`end_date`，"至今"转换为当前月份字符串 `"present"` 或 ISO 日期。
  - **描述**：该条目剩余文本。
- 对无法识别的条目标记 `"confidence": "low"`。

### 5.6 置信度规则

| 置信度 | 含义 | 前端提示 |
|--------|------|----------|
| `high` | 强规则命中，可信 | 正常显示 |
| `medium` | 启发式命中，可能有小错 | 黄色边框/图标提示"请确认" |
| `low` | 未命中、多候选或解析异常 | 红色边框/图标提示"请补充或核对" |
| `missing` | 字段缺失 | 占位提示"未识别" |

置信度按字段独立计算，规则由单元测试覆盖。

## 7. 前端改动

### 7.1 `CandidateForm.vue`

- 解析成功后，把返回的所有字段回填到表单：
  - `name`、`phone`、`email`、`position`、`education`、`experience_years`、`source`、`summary`、`skills`、`experiences`。
- 工作经历追加到现有列表，不覆盖用户已填写内容。
- 根据 `confidence` 给字段加视觉提示：
  - `medium`：输入框右侧显示黄色 `el-icon-Warning` 提示"请确认"。
  - `low` / `missing`：输入框红色边框，提示"未识别，请补充"。
- 解析失败时给出明确提示："文件解析失败，请手动填写"或"扫描件无法自动解析"。

### 7.2 交互细节

- 上传简历解析按钮保留在"新增候选人"页面顶部。
- 解析完成后自动滚动到第一个低置信字段。
- 用户提交表单时，不再校验解析来源，允许用户自由修改。

## 8. 错误处理与降级

| 场景 | 处理 |
|------|------|
| 文件格式不支持 | 返回 400，前端提示"仅支持 PDF、Word、Excel" |
| 文件过大 | 返回 400，前端提示"文件大小不能超过 10MB" |
| PDF 无文本层（扫描件/图片） | 返回 200，但所有字段为 null，confidence 全为 missing，前端提示"扫描件无法自动解析" |
| 部分字段提取失败 | 返回已有字段，缺失字段为 null，前端允许手动补充 |
| 解析过程中异常 | 返回 500，maskError 脱敏，前端提示"解析失败，请手动填写" |

## 9. 测试与验收标准

### 9.1 单元测试

为 `talent_parsers.js` 新增测试用例（如项目已有测试框架则复用，否则用最小化测试脚本）：

### 9.2 验收标准

- 常见招聘平台导出简历：姓名、手机号、邮箱提取准确率 ≥ 90%。
- 普通自由格式 PDF/Word 简历：姓名提取准确率 ≥ 75%。
- 工作经历正确拆分为多条（公司+职位+时间）≥ 70%。
- 前端所有解析字段均可自动回填。
- 低置信字段有明显视觉提示。
- 解析失败时有降级提示，不影响手动录入。

## 10. 风险与约束

- **扫描版 PDF**：纯文本提取无法识别图片，需要后续接入 OCR（本期不做）。
- **复杂排版**：分栏、表格简历可能导致区块切分错误，需要持续积累规则。
- **性能**：大文件解析在 Workers 50ms/10MB 限制内应无压力，但仍需测试 10MB 边界。
- **数据隐私**：简历原文仅在 Worker 内存中处理，不发送给外部服务，符合项目约束。
