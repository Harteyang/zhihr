# 复盘数据分析看板 - 开发需求文档

> **项目定位**：独立于复盘系统的纯前端数据分析看板  
> **数据源**：**云端 API**（Cloudflare D1 数据库），通过复盘系统后端获取  
> **认证方式**：复用 `shared-auth.js` 统一认证模块，与复盘系统共享登录状态  
> **技术栈**：纯前端 HTML/CSS/JavaScript + ECharts + Tailwind（与 zhihr 现有工具一致）  
> **部署方式**：静态文件，`zhihr/review-analytics/index.html`，集成到主导航页

---

## 一、整体目标

将每日复盘积累的 8 维度结构化数据转化为可视化洞察，帮助用户：

1. **看清趋势** — 各维度的长期变化曲线
2. **发现模式** — 维度间的关联和周期规律
3. **量化评估** — 生活平衡度、各维度健康指数
4. **智能预警** — 异常行为和风险提示

---

## 二、数据模型回顾

### 2.1 数据来源

**数据源：云端 API（Cloudflare D1 数据库）**，通过复盘系统后端 API 获取。

API 地址：`https://api.zhihr.vip/api/reviews`  
认证方式：`Authorization: Bearer <token>`（复用 `shared-auth.js` 统一认证）  

拉取所有记录：
```javascript
GET /api/reviews?pageSize=1000
Authorization: Bearer <token>
```

返回格式为 `ReviewApiResponse[]`，经 API 层转换后如下：

```typescript
interface Review {
  id: string
  date: string           // "2026-05-28"，API 返回字段名为 review_date → 映射为 date
  summary: string        // API 返回字段名为 title
  content: {
    [dimensionKey]: string  // JSON.stringify(DimensionData)，API 返回时已自动 JSON.parse
  }
  createdAt: string      // API 返回字段名为 created_at
  updatedAt: string      // API 返回字段名为 updated_at
}
```

> **注意**：API 返回的字段名是 snake_case（如 `review_date`、`created_at`），前端需要做字段映射。

### 2.2 八大维度结构化字段

| 维度 | key | 结构化字段 |
|------|-----|-----------|
| 身体健康 | health | sleep（睡眠）、diet（饮食）、exercise（运动） |
| 工作事业 | work | task（任务情况）、hours（工作时长） |
| 学习成长 | study | subject（学习内容）、hours（学习时长） |
| 人际关系 | social | activity（互动人群）、mood（能量增减） |
| 财务经济 | finance | income（收入）、expense（支出） |
| 生活事物 | life | activity（家庭氛围）、mood（家庭事物） |
| 精神世界 | spirit | reading（阅读/输入）、reflection（反思） |
| 休闲娱乐 | leisure | activity（放松充电）、duration（娱乐项目） |

### 2.3 数据解析函数

```typescript
interface DimensionData {
  structured: { [itemId: string]: string }  // { sleep: "7小时", exercise: "30分钟" }
  freeform: string
}
```

> **注意**：API 返回的 `content` 字段已经是解析后的对象（`JSON.parse` 已在 API 层完成），所以 `content[key]` 可能是对象（`DimensionData`）也可能是字符串。解析时需要兼容两种格式。

## 三、功能模块

### 模块 1：概览仪表盘（Dashboard）

**目标**：一眼看清整体复盘状态

| 指标 | 说明 |
|------|------|
| 总复盘天数 | 有记录的总天数 |
| 本月复盘天数 | 本月有记录的天数 |
| 连续复盘天数 | 从今天往前的连续记录天数 |
| 总维度记录数 | 所有维度被记录的总次数 |
| 最活跃维度 | 被记录最多的维度 |
| 最不活跃维度 | 被记录最少的维度 |

**可视化**：
- 顶部 6 个指标卡片（类似现有 ReportTab 但更丰富）
- **月度日历热力图**：一整月的复盘记录热度展示（绿色深浅表示维度覆盖度）
- **八维雷达图**：显示各维度的活跃度（近 30 天）

### 模块 2：趋势分析（Trends）

**目标**：展示各维度的时序变化趋势

#### 2.1 维度选择器
- 顶部 Tab/下拉选择单个维度，或勾选多个维度对比
- 快捷按钮：「全部」「健康」「工作」「学习」等

#### 2.2 结构化字段趋势图

对每个维度的**数字类结构化字段**绘制折线图：

| 维度 | 可量化字段 | 提取规则 |
|------|-----------|---------|
| health | 睡眠（小时） | 提取 `sleep` 值中的数字（如"7小时"→7） |
| health | 运动（分钟） | 提取 `exercise` 值中的数字 |
| work | 工作时长 | 提取 `hours` 值中的数字 |
| study | 学习时长 | 提取 `hours` 值中的数字 |
| finance | 收入/支出 | 提取 `income`/`expense` 值中的数字 |

**交互**：
- X 轴：日期（可缩放）
- Y 轴：数值
- 悬浮显示具体数值
- 时间范围选择器（7 天 / 30 天 / 90 天 / 全部）
- 移动端支持手势缩放

#### 2.3 文本类字段词云

对以下维度的自由文本生成词云：

- `study.subject` — 学习内容
- `spirit.reading` — 阅读内容
- `spirit.reflection` — 反思感悟
- 各维度的 `freeform` 自由文本

**交互**：
- 可选择维度切换词云
- 词频统计列表（Top 20）
- 点击词条跳转到包含该词的所有记录

#### 2.4 维度活跃度趋势

堆叠柱状图，显示每天记录了哪些维度：
- X 轴：日期
- Y 轴：活跃维度数量（0-8）
- 柱体分段着色，每段代表一个维度
- 鼠标悬浮显示当天各维度详情

### 模块 3：交叉分析（Cross Analysis）

**目标**：发现维度间的关联规律

#### 3.1 相关性矩阵

8 个维度两两之间的**活跃度相关系数**热力图：
- 基于"同一天两个维度同时被记录"的频率
- 颜色深浅表示相关性强弱
- 点击色块显示详细对比

#### 3.2 维度联动分析

选择两个维度，叠加显示它们的变化曲线：
- 主图：双 Y 轴折线图（如睡眠时长 vs 工作时长）
- 辅助信息：两条曲线的相关系数 r 值
- 数据点可悬浮查看详情

#### 3.3 工作日 vs 周末对比

自动区分工作日和周末，对比分析：
- 柱状对比图：工作日各维度活跃度 vs 周末
- 哪些维度在工作日更活跃？哪些在周末？
- 结构化字段的均值对比（如工作日睡眠 vs 周末睡眠）

### 模块 4：月度报告（Monthly Report）

**目标**：每月自动生成一份结构化的复盘报告

#### 4.1 月度概览
- 本月复盘天数 / 缺席天数
- 连续复盘最长的天数
- 各维度活跃度排名

#### 4.2 维度评分雷达

基于结构化数据给每个维度打分（0-100）：

| 维度 | 评分规则 |
|------|---------|
| 健康 | 睡眠≥7h 加分、有运动加分、坚持饮食加分，取月均值 |
| 工作 | 工作饱和度评估、工作记录频次 |
| 学习 | 学习天数占比、学习内容多样性 |
| 社交 | 社交活动频率、能量增减判断 |
| 财务 | 收支记录完整性 |
| 生活 | 家庭记录频率 |
| 精神 | 阅读/反思记录频次 |
| 休闲 | 休闲记录频率 |

#### 4.3 进步与退步

- 对比本月 vs 上月的各维度评分变化
- 绿色箭头 ↑ 表示进步，红色箭头 ↓ 表示退步
- 变化最大的前 3 个维度突出显示

#### 4.4 月度关键词

- 从本月所有自由文本中提取 Top 10 关键词
- 生成月度词云
- 关键词 vs 上月的差异对比

#### 4.5 一句话总结（AI 生成）

基于本月数据，生成一句总结性建议。例如：
> "本月睡眠质量提升显著，但社交互动偏少，建议下月多安排社交活动。"

> **注**：此功能需要接入 AI API（如 DeepSeek/通义千问），可作为 V2 功能。

### 模块 5：预警与建议（Alerts）

**目标**：自动检测异常和风险

#### 5.1 异常检测规则

| 规则 | 触发条件 | 预警级别 |
|------|---------|---------|
| 睡眠不足 | 连续 3 天睡眠 < 6h | ⚠️ 黄色 |
| 连续加班 | 连续 5 天工作时长 > 10h | ⚠️ 黄色 |
| 学习中断 | 连续 7 天无学习记录 | 🔴 红色 |
| 社交断连 | 连续 14 天无社交记录 | 🔴 红色 |
| 运动荒废 | 连续 7 天无运动记录 | ⚠️ 黄色 |
| 支出异常 | 单日支出 > 月均 3 倍标准差 | ⚠️ 黄色 |
| 复盘缺席 | 连续 3 天无复盘记录 | ⚠️ 黄色 |

#### 5.2 建议生成

每个预警关联一条建设性建议：
- 睡眠不足 → "建议今晚提前 30 分钟上床"
- 学习中断 → "试试每天 15 分钟微学习"
- 社交断连 → "周末约朋友喝杯咖啡"

#### 5.3 预警看板

- 列表展示所有活跃预警
- 按严重程度排序（红色 > 黄色）
- 每条预警显示：触发规则、持续时间、相关数据
- 可标记"已读"或"忽略"

### 5.4 数据读取

```javascript
// 1. 初始化认证
SharedAuth.init()

// 2. 从云端 API 拉取复盘数据
async function loadReviewsFromCloud() {
  if (!SharedAuth.isAuthenticated()) {
    showLoginPrompt()
    return []
  }
  
  const result = await SharedAuth.apiRequest('/api/reviews?pageSize=1000')
  
  if (!result.success) {
    showError(result.message)
    return []
  }
  
  // API 返回的 content 已经是解析后的对象，直接使用
  return result.data.map(r => ({
    id: r.id,
    date: r.date,
    summary: r.title || '',
    content: r.content || {},
    createdAt: r.createdAt,
    updatedAt: r.updatedAt
  }))
}

// 3. 解析每个维度的结构化数据
function parseDimensionValue(value) {
  // API 返回时已经 JSON.parse 过了，value 可能是对象或字符串
  if (!value) return { structured: {}, freeform: '' }
  
  if (typeof value === 'object' && value.structured !== undefined) {
    return value
  }
  
  if (typeof value === 'string') {
    try {
      const parsed = JSON.parse(value)
      if (parsed && parsed.structured) return parsed
    } catch {}
    return { structured: {}, freeform: value }
  }
  
  return { structured: {}, freeform: '' }
}

// 4. 提取数值
function extractNumber(str) {
  if (!str) return null
  const match = str.match(/(\d+(\.\d+)?)/)
  return match ? parseFloat(match[1]) : null
}
```

### 5.5 页面生命周期

1. 页面加载 → `SharedAuth.init()` 初始化认证
2. 检查登录状态 → 未登录显示引导，已登录拉取数据
3. 调用 `GET /api/reviews` 获取所有复盘记录
4. 数据解析 → 字段映射 → 缓存到内存变量
5. 渲染图表（ECharts 图表在数据就绪后初始化）
6. 监听 `auth:change` 事件 → 登录/登出时自动刷新
7. 页面刷新 → 重新走 1-5 流程

## 七、数据安全与隐私

- 认证 token 由 `shared-auth.js` 管理，存储在 localStorage
- API 调用通过 `SharedAuth.apiRequest()` 自动携带 token
- token 过期时自动刷新，刷新失败时自动登出
- 所有数据仅在前端展示，不上传第三方服务
- 如未来加入 AI 分析功能，需用户明确确认后才会发送数据

## 十、附录

### 10.1 与现有复盘系统的关系

| 对比项 | 复盘系统 | 分析看板 |
|--------|---------|---------|
| 定位 | 数据采集 | 数据分析和可视化 |
| 读写 | 读写 localStorage + 云端 API | **只读云端 API** |
| 依赖 | 有后端 API | 引用 shared-auth.js，依赖后端 API |
| 数据 | 产生数据 | 消费数据 |
| 认证 | 内置登录注册 | **复用 shared-auth.js，共享登录状态** |
| 部署 | Cloudflare Workers + Pages | 纯静态文件（同域名下） |

### 10.2 可能的风险与应对

| 风险 | 应对 |
|------|------|
| API 请求失败或超时 | 显示友好错误信息 + 重试按钮 |
| token 过期 | SharedAuth 自动刷新或登出 |
| ECharts 渲染性能（大量数据点） | 采样降维，只显示关键数据点 |
| 移动端图表交互不佳 | 简化交互，增加全屏查看模式 |
| 复盘系统数据格式变更 | 定义数据版本号，向前兼容解析 |
